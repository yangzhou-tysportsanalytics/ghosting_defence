# ghost-defense

Matchup inference, ghost defenders and defensive-positioning measures on the public 2015-16 NBA
SportVU tracking data (631 games, October 2015 – January 2016).

This repository contains the code, the aggregate results and a link to the derived data behind
our MIT Sloan Sports Analytics Conference 2027 research paper (release v1.2) and its earlier
abstract. It covers:

- **Possessions and ball handlers**: half-court possession windows at 5 Hz, mapped to one basket.
- **Matchup inference**: the hidden Markov model of Franks et al. (2015), fitted by EM, with
  strong-side / weak-side emission weights and a help (no man) state.
- **Screen defence**: switches and third-defender help on on-ball screens.
- **Rule ghost and deviations**: each defender's league-average position given the offence (the
  fitted mixture of his man, the ball and the rim), per-defender deviation and "sag" toward the
  rim, split-half reliability, and a hierarchical team / within-team decomposition.
- **Learned ghost**: an online masked-completion transformer with a Gaussian-mixture density
  over the defenders: a team ghost (all five hidden) and an individual ghost (one hidden, the four
  real teammates visible). Each component mean is a learned correction to the rule ghost
  (attention over the attackers' rule positions plus an offset, D-022). Deviations are
  cross-fitted over five folds, so no deviation is in-sample. "Online" refers to the offence and
  context: the velocity inputs are central differences and so look 0.2 s ahead. With strictly
  past-only velocities the final model's test NLL rises by 0.017 (team) and 0.053 (individual),
  about 3 % of its advantage over the rule ghost, without retraining; a causally trained
  prototype fits as well as the original (`phase3_lookahead_sharpness.py`, D-031).

Ghosts here are *descriptive*: where a league-average defender would be given the offence, not
where a defender should have been. Player-level numbers describe observed positioning; they are
not a ranking of defenders.

## Reproducing

Requirements: [uv](https://docs.astral.sh/uv/), Python 3.12, about 3 h on a 16-core laptop CPU for
the full season, except the learned ghost. Training the learned ghost needs a GPU (17 hours on
one H100 MIG slice); `scripts/gpu.py` runs it as resumable steps, also in short Slurm jobs
(`scripts/slurm_ghost.sbatch`), and `scripts/gpu.py selftest` checks every step on a few batches.

Use the current `main` branch. The commit tagged `data-v1.1` locks an earlier nbacore commit
that is no longer in nbacore's public history (the code is the same; only comments changed), so
installing from that tag may fail. The `data-v1.1` derived-data package is unchanged and
remains valid.

```bash
uv sync
uv run pytest -q
```

The pipeline reads per-frame tracking data, which is not distributed: build the nbacore data
release `v1.6` from the raw logs with the nbacore code (see its README), then point
`NBA_DATA_ROOT` at it:

```bash
export NBA_DATA_ROOT=/path/to/nba_data
bash scripts/pipeline_all.sh          # or: make pipeline-all
uv run python scripts/make_figures.py
```

Without the tracking data, the team- and player-level results can be recomputed from the
derived-data package (e.g. the team correlations from `team_screen_defense.csv` and
`team_points_allowed.csv`; reliability from `rule_ghost_deviations.parquet`).

## Pipeline steps

Scripts are numbered by pipeline stage (`phase1_…` to `phase5_…`); each stage reads the outputs
of the previous one. `scripts/pipeline_all.sh` runs them in dependency order.

| stage | script | what it does |
|---|---|---|
| 1. Possessions | `phase1_possessions.py` | half-court possession windows (midcourt crossing → shot release / turnover / foul), mapped to one basket, resampled to 5 Hz; ball handler per frame |
| 2. Matchups and events | `phase2_matchups.py` | fits the matchup HMM (EM) and labels who guards whom at every step |
| | `phase2_em_init_sensitivity.py` | refits the HMM from several starting points (robustness of the weights) |
| | `phase2_events.py` | changes of matchup and help events |
| | `phase2_screen_events.py` | links matchup changes to screens (screen switches) and finds closeouts |
| | `phase2_screen_rates.py` | switch rates per screen |
| 3. Learned ghost | `phase3_export_arrays.py` | packs the model inputs per split (private: contains positions) |
| | `phase3_train.py` | trains / evaluates the ghost model (league, lineup or scheme; cross-fitting folds) |
| | `phase3_gpu.sh` | GPU stages: check, smoke, sweep, final (test once), ablation, conditions, cross-fitting, deviations |
| | `phase3_multimodality.py`, `phase3_overlay.py` | multimodality at screens; overlay videos (kept private) |
| 4. Deviations and models | `phase4_rule_ghost.py` | league-average rule ghost; per-defender deviation and sag |
| | `phase4_learned_ghost_dev.py` | out-of-fold learned-ghost deviations (negative log density, distance to the nearest mode) |
| | `phase4_phase_context.py` | phases of each defender-step and help-geometry descriptors |
| | `phase4_reliability.py` | split-half reliability, stability curves, team vs player variance (`--context phases`: main specification) |
| | `phase4_hier.py` | hierarchical model: team means and within-team player effects with intervals (`--context phases`) |
| | `phase4_breakdowns.py` | breakdown events (reference computation on the rule ghost) |
| | `phase4_xfg_data.py`, `phase4_xfg.py` | shot table and expected field-goal (xFG) model |
| | `phase4_ghost_points.py` | xFG at real vs ghost defender positions |
| 5. Validation | `phase5_predictive_validity.py` | deviations before the shot vs openness and xFG at the release; out-of-sample player level |
| Analyses | `analysis_team_screen_defense.py` | team switch and help rates on on-ball screens |
| | `analysis_team_validity.py` | team rates vs points allowed, with robustness and intervals |
| | `analysis_help_timing.py` | help delay after screen contact, early-help rates, screen-confidence sensitivity |
| | `analysis_help_value.py` | play-level association of help with points and shot quality |
| | `analysis_player_validity.py` | player measures vs public defensive metrics |
| Sensitivity | `second_chance_sensitivity.sh` | reruns the chain with second-chance possessions (`build_windows_second_chance.py`) and compares (`compare_second_chance.py`) |
| Video check | `select_quick_check.py`, `make_quick_check.py`, `make_quick_adjudication.py` | sample and offline pages of the held-out video check (`tools/quick_check/`; pages contain positions and are not distributed) |
| | `quick_check_eval.py` | matchup accuracy and event precision against the two analysts and their consensus |
| Outputs | `make_figures.py` | figures and tables in `paper/` |
| | `ssac_figures.py`, `ssac_cards.py`, `ssac_figure1.py` | figures, cards and the review queue of the SSAC paper |
| | `build_derived_release.py`, `check_release.py` | derived-data package and its no-tracks check |

Results are written to `reports/<stage>/<data version>_<game set>/`, e.g.
`reports/phase4/v1.6_all/` = stage 4 on nbacore data v1.6, all games; team and player analyses
go to `reports/analysis/`.

## Repository layout

```
src/ghost/        package: possessions, tensors, matchup HMM and events, ghost models, xFG,
                  hierarchical model
scripts/          one entry point per step; pipeline_all.sh runs them in order
configs/          data version pin and game sets
reports/          aggregate results (JSON / CSV / PNG), no coordinates
paper/            figures and tables generated by scripts/make_figures.py
docs/             design decisions, data schema
tests/            unit tests (tests that need local data are skipped without it)
```
